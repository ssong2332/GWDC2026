# ADR-0003: 증거 원문은 SQLite에 저장하고 JSON으로 repo에 내보내며, 온체인에는 해시만 올린다 (IPFS 대신)

> 상태: 제안
> 날짜: 2026-09-28

## 맥락

- 결제·차단·승인·중지 각 사건의 원문(정책·요청·AI 판단·토큰·tx)을 남기고, 온체인에는 해시만 올린다 (PRD F-11, 사용자 답 U-R4 "SQLite 로컬 DB (추천)").
- 제3자가 운영자에게 묻지 않고 repo의 증거 JSON + 공개 RPC만으로 재구성해야 한다 (F-12).
- 비용 0원 목표(N-06), 로컬 실행(N-09), 1인·2일 일정.
- 해시가 일치하려면 같은 객체가 항상 같은 바이트로 직렬화되어야 한다.

## 검토한 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| A. SQLite 원문 + JSON 내보내기(repo 커밋) + 이벤트에 `keccak256(JCS(package))` | 추가 인프라·비용 0. 공개 repo가 곧 공개 저장소. 검증 스크립트가 파일 1개 + RPC로 동작 | 내보내기를 잊으면 공개본이 낡는다(수동 단계). 원문 가용성이 GitHub에 의존 |
| B. IPFS(핀닝 서비스)에 원문, 이벤트에 CID | 콘텐츠 주소 지정 표준, 원문 위치가 체인에 박힘 | 핀닝 계정·키·비용·가용성 관리 필요. 오프라인 데모에 불리. 일정 대비 이득 작음 |
| C. 원문 전체를 이벤트 데이터로 온체인 | 체인만으로 완결 | Kiln 판단 문장·정책 원문으로 가스 폭증, 개인 입력(위임 문장)이 영구 공개 |

## 결정

A. 결정적 이유: 사용자 답(SQLite + 해시만 온체인)과 비용 0원을 만족하면서, 공개 repo가 그대로 제3자용 원문 저장소가 된다.

- 정규화: RFC 8785 JCS(npm `canonicalize`), 해시: keccak256 (EVM 네이티브, viem 내장, 검증자가 Solidity와 같은 함수 사용).
- 금액은 10진 문자열, 정수 카운트만 JSON 숫자, Kiln `cost`도 문자열 — 언어 간 부동소수 표현 차이 제거.
- 순환 방지: 패키지는 tx 전에 만들고 해시를 tx에 싣는다. tx hash·블록·로그 위치는 해시 대상이 아닌 `anchor`에 둔다.
- 스키마·경로·검증 절차는 docs/Architecture.md "데이터 모델과 인터페이스 > 5. 증거 패키지".

## 결과 (트레이드오프 포함)

- 얻는 것: `evidence/base-sepolia/evidence.json` + `cli/verify-evidence.ts` + 공개 RPC만으로 재해시·이벤트 대조·정책 범위 재생이 된다. 변조된 필드는 해시 불일치로 드러난다(F-12 ②).
- 감수하는 것: Base Sepolia 실행 후 `evidence:export`를 수동으로 돌려 커밋해야 한다(README에 순서 명시 — docs 담당). 로컬 SQLite를 지우면 내보내지 않은 원문은 사라진다(온체인 해시는 남지만 대조 대상이 없어짐). 위임 문장 원문이 공개 repo에 올라가므로 데모 문장에 개인정보를 넣지 않는다.
