## 검토한 대안

### (1) 문구 전환 메커니즘

| 대안 | 장점 | 단점 |
|---|---|---|
| A. `next-intl` | Next App Router 공식 사례, ICU 복수형, 서버 컴포넌트 지원 | 새 의존성 + 설정(`i18n/request.ts`, 플러그인, 보통 `[locale]` 라우트 세그먼트나 미들웨어)이 동결 하루 전에 들어온다. 문구가 2개 언어·수백 개 규모라 기능 대부분이 쓰이지 않는다. 설정 실수 시 빌드 전체가 깨진다 |
| B. `i18next` + `react-i18next` | 널리 쓰임, 네임스페이스·보간 | 의존성 2개, 초기화·SSR 연동을 직접 해야 한다. 키가 문자열이라 누락 키가 컴파일 때 잡히지 않는다(타입 확장 설정 필요) |
| C. 자체 타입 사전(`en.ts`·`ko.ts`) + React context | 의존성 0. `ko: Messages`(= `typeof en`) 타입 한 줄로 누락·잉여 키가 `tsc`에서 잡힌다. 값을 함수로 두면 복수형·보간도 타입 검사된다. 코드 몇십 줄 | 복수형 규칙·날짜 로케일 등 라이브러리 기능이 없다(두 언어뿐이고 숫자·날짜 형식은 고정 — D-42 — 이라 필요 없음). 세 번째 언어가 생기면 재검토 |

### (2) 선택 보관 위치와 첫 화면 적용

| 대안 | 장점 | 단점 |
|---|---|---|
| 1. 쿠키 `lang` + 루트 레이아웃이 `cookies()`로 읽어 SSR | 첫 HTML부터 선택 언어·`<html lang>`이 맞다 → 깜빡임·hydration 불일치 없음. 새로고침·화면 이동·브라우저 재시작(Max-Age) 모두 유지. 라우트 구조 불변 | 루트 레이아웃이 요청 데이터를 읽으므로 모든 페이지가 동적 렌더링이 된다(정적 사전 렌더 손실 — 로컬 단일 사용자 데모라 체감 영향 없음, 추정). 쿠키가 API 요청에도 실린다(Route Handler가 읽지 않으면 무해) |
| 2. localStorage + 마운트 후 적용 | 서버 무관, 구현 단순 | 서버는 항상 기본(ko)으로 그리므로 영어 선택자는 새로고침마다 한국어→영어 깜빡임. `<html lang>`이 첫 HTML에서 틀린다(①⑤ 브라우저 확인에서 걸릴 수 있음) |
| 3. localStorage + `<head>` 인라인 스크립트로 hydration 전 적용 | 깜빡임 일부 감소 | 텍스트는 React가 그리므로 인라인 스크립트로는 `lang` 속성만 바꿀 수 있다 — 본문은 여전히 깜빡이거나 hydration 불일치 경고. 인라인 스크립트는 CSP·`dangerouslySetInnerHTML` 금지 규칙(Architecture 10절 "출력 안전")과 부딪힌다 |
| 4. URL 접두사 `/ko/…`·`/en/…` | 링크만으로 언어가 전달된다 | 라우트 전체 이동(`app/[locale]/…`), NavBar·리다이렉트·감사 공유 URL(`/audit?tx=`) 형식 변경. 동결 직전 변경 범위가 가장 크다. 쿠키 없이 북마크로 들어오면 선택이 유지되지 않는다(⑤와 어긋남) |

## 결정

**(1) C 자체 타입 사전 + React context, (2) 1 쿠키 `lang` + 루트 레이아웃 SSR 읽기.** 결정적 이유: 새 의존성 없이 "첫 HTML부터 올바른 언어·`lang`"(F-17 ①⑤)과 "누락 키 컴파일 검출"을 동시에 얻는 가장 작은 조합이다. 세부 규격은 Architecture.md 10절 "UI 언어 (F-17)" 소절.

## 결과 (트레이드오프 포함)

- 얻는 것: 깜빡임 없음, 새 패키지 0개, 누락 키는 `tsc`와 단위 테스트 두 겹으로 잡힘. API·코어·CLI·증거 코드는 바뀌지 않는다(언어는 브라우저 컴포넌트에서만 쓰인다 — F-17 ④ 경로 차단).
- 감수하는 것: 모든 페이지가 동적 렌더링이 된다(`npm run build` 출력의 라우트 표시가 바뀜 — 추정, 확인: T-17 빌드 로그). 쿠키를 막은 브라우저는 새로고침마다 한국어로 돌아간다. 복수형·로케일 형식 기능은 없다(필요해지면 이 ADR을 대체).
- 동결 위험 대응: T-17은 4화면 + 언어 선택 버튼을 한 단위로 병합한다(한 화면만 한국어인 부분 병합 금지). 미완이면 병합하지 않으면 되므로 기존 영어 UI가 그대로 남는다(OQ #27 답과 일치).
